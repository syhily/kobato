# Inkling Editor

A Lexical-based rich-text editor built around cards — block-level embeds (image, video, button, bookmark, …) that live inside the document but behave as atomic units.

## Language

**Card**:
A block-level embed in the document (image, video, gallery, button, bookmark, callout, toggle, header, file, audio, html, code block, horizontal rule, math). Atomic from the writer's perspective: selected as a unit, deleted as a unit. The table element family is deliberately not a card — its cells hold editable inline text with a real Lexical selection, which the decorator card pipeline cannot provide — so "card" never names tables.
_Avoid_: decorator, embed, block

**Card adjacency**:
The state of the caret or selection sitting immediately before or after a card. Comes in two notions: **visual adjacency** (the caret's rendered position, derived from geometry — what arrow keys care about) and **logical adjacency** (the selection anchor's offset — what backspace/delete care about). The adjacency module (src/plugins/behaviour/card-adjacency.ts) also owns the destructive-key policies: `dispatchSelectedCardDeletion` — the one home of the "selected card eats the destructive key" gate (focus guard + `DELETE_CARD_COMMAND` with the handler's direction; backspace/delete/delete-line call it as their first policy gate, each keeping its own focus-swallow policy) — the direction-parameterized mirror surgeries `$removeLogicallyAdjacentCard` ("key eats the adjacent card, caret stays put": 'previous' keeps backspace's two extra guards, 'next' is unguarded) and `$removeEmptyBlockAndSelectCard` ("delete the empty block, select the adjacent card"), whose deliberate empty-block divergence is the named `EmptyBlockCheck` policy ('paragraph-is-empty' for backspace vs 'from-mode-blank' for forward delete — from-mode, not selection-mode) — and `$removeOrReplaceNodeWithParagraph`, the empty-card removal surgery with a named **focus policy** (`'decorator-next'` default vs `'root-first'` for ctrl/cmd+Enter leaving edit mode — the divergence that used to be enter.ts's private copy of the surgery). Its `$selectCard` is the one home of the select-a-card operation: a node selection plus a named **selection focus policy** (`'if-blurred'` default for pointer-driven selection, `'always'` for removal/external-control repair, `'never'` — the bare `$selectDecoratorNode` primitive — for keyboard navigation that already owns focus). The repair never scrolls the viewport: the one inherited `focus()` call without `preventScroll` was drift between two lineages, unified on `preventScroll: true`.
_Avoid_: next-to-card, beside-card

**Card spec**:
The declarative definition of a card — its properties, card menu, nested editors, and transient state — from which the card's node behaviour is produced. Simple cards are nothing but their spec. The transient/nested-editor field vocabulary is single-sourced from the spec at the type level — names AND value types: the spec arrays are `as const satisfies` on the declaration, every transient entry's `initial` lambda annotates its return type (the field's value type), a nullable nested editor is built with `nullableNestedEditor` (a type-level brand carries `LexicalEditor | null`; plain literals derive a non-null editor), and `CardSpecFieldMap<typeof declaration>` (exported from the public barrel, defined beside the generator) derives the whole `__*` map. The map rides the assembled class's instance type (`assembleCardNodeOnce` folds it in), so the shims are re-exports plus their dataset types with no hand-written map or cast — renaming or retyping a spec entry is a compile error at every consumer. The base class's `declare __*` leg cannot derive (a base cannot import its declaration), so it stays the one hand-written site, pinned against the derived map by `test/typecheck/card-spec-field-agreement.ts`; `card-declarations.test.ts` pins the constructed/dataset agreement at runtime. The dataset-property spec also carries per-card serialization/edit policy: `invalidates` (the artifact-slot edit-invalidation, enforced by the generated setters) and `redactDataUrl` (the blob guard in the generated exportJSON — video/file have no overrides left; image keeps its byte-order override but shares `redactDataUrlValue`). Transient entries may carry `accessor: true` — assembly defines the get/set pair from the spec (`CardSpecAccessorMap` derives its type), and the base classes keep type-only `declare` legs so base-typed write-seam consumers can name the accessor; the four upload cards share one const entry (`transientTriggerFileDialogProp`, and `transientInitialFileProp` for the INSERT_MEDIA_COMMAND initial file — one `File | undefined` value type for all four; video's former `File | null` was drift). The five captioned cards share one nested-editor factory (`captionEditorSpec`, src/nodes/cards/caption-editor-spec.ts — in the cards layer because the generator must not import MINIMAL_NODES): per-card variance is data (`nullable: true` for the round-trip-detached gallery/video, `cleanBasicHtml` for image). The runtime-width cards' decorate width mapper is single-homed too (`decorateCardWidth`, beside `normalizeCardWidth`). The generator's options bag carries `hasEditMode` as data (image/gallery/horizontalrule/footnotedefinition pass false — no method overrides left).
_Avoid_: card config, card definition

**Card declaration**:
The single per-card source of truth naming everything the editor must know about a card: its card spec, whether (and how) it joins the markdown round-trip (the `markdown` spec — `{ kind: 'fence' }` or `{ kind: 'exempt' }`), its insert-spec flags (edit-mode, media claiming — the insert command itself derives from the node type, never declared), its toolbar label (`toolbarLabel` — the `data-inkling-card-toolbar` selector contract), and, for the four media cards, its `uploadType`. The declarations come from two sources read together: the closed built-in set `CARD_DECLARATIONS` and the host cards' registry (`getHostCards()`, src/nodes/cards/host-card-registry.ts). Every registry is a derived view over the card declarations — the node sets (`getEditorCardNodes`), the menus, the decorate targets, the insert registrar (`CardInsertPlugin`), the toolbar label (`getCardToolbarLabel`, beside the merge policy in card-facts), and the markdown fence payloads (src/nodes/cards/card-markdown-transformers.ts). Every derived view resolves its card facts through one merge-policy module — `resolveCardFacts` / `resolveAllCardFacts` (src/nodes/cards/card-facts.ts): built-in declaration first, host registry fallback, so the "host cards never override built-ins" invariant has exactly one home. The host registry stores the raw host spec (a neutral fact store), and both sources flow through the same per-view projectors — `resolveCardMenuEntries` / `resolveCardDragIcon` (card-menus), `resolveCardDecorateTarget` (card-decorate — each card's `render*Card` lives beside its component in the `src/nodes/*NodeComponent.tsx` files, paired with the declaration by the exhaustive `CARD_DECORATE_MODULES` record), the insert projection (card-insert-commands, which derives the host class through the same memoized assembler `defineCard` used) — so no projection is implemented twice. The layering rule behind the pipeline (declarations React-free, the registry layer never value-imports the wrapper layer, `getEditorCardNodes` off the wrapper registry) is pinned statically by `test/unit/nodes/card-layering-imports.test.ts`. The insert commands' payload types are DERIVED, not hand-restated: each declaration exports its spec arrays (`nestedEditors`/`transientProps`), and `card-commands.ts` composes each public `*NodeDataset` from the base module's `*Data` plus `CardSpecTransientDataset` / `CardSpecNestedEditorDataset` over those arrays — the shims re-export the types, so the registry layer never imports from the wrapper layer, and a spec rename/retype is a compile error at the command (the derivation reads the spec arrays rather than `typeof declaration` because a declaration's menu entries carry the commands — a whole-declaration derivation would close a type-inference cycle). Node sets compose in DECLARATION order everywhere (registration order carries no runtime semantics — node types are unique, replacements ride the named extended pairs); the former legacy-order slot machine and `MARKDOWN_CARD_ORDER` are deleted, and the literals in `test/unit/nodes/derived-node-sets.test.ts` guard drift from declaration order, not history.
_Avoid_: card registration, card manifest

**Editor surface**:
One of the shipped top-level editor compositions — the default editor (`InklingEditor`) and the markdown round-trip. Each is a preset over the shared composer: its own node set (derived from `EDITOR_BASE_NODES`), its plugins (the core mount set `CORE_PLUGINS` every `InklingComposableEditor` renders, plus the surface's feature plugins `DEFAULT_FEATURE_PLUGINS` — both data lists, snapshot-pinned), its markdown transformers. A card declaration's `markdown` spec names whether (and how) the card joins the round-trip; there is no runtime surface query — a card is present on a surface because that surface composed its node in. `InklingSurface` (src/components/InklingSurface.tsx) is the composition rule made exportable: a custom host surface wraps its top-level editor tree in exactly one (inside an `InklingComposer`), so nested card editors share the top-level undo stack and `onChange`. The published package layers the surfaces across two entries: `.` carries the full editor, while `./core` (plan C5) ships only the card-free composition pieces — the core `InklingComposer` (required `nodes`), `InklingSurface`, `InklingComposableEditor`, `CORE_PLUGINS`, `RestrictContentPlugin`, and the `MINIMAL`/`BASIC` node and transformer sets. The `.` barrel exports the whole card family (the 14 card classes with their guards, factories, dataset and serialized types, and every insert command), so a host can compose a subset surface from `EDITOR_BASE_NODES` plus picked cards.
_Avoid_: environment, platform

**Import spec**:
The card declaration's DOM-import knowledge — how the card's markup reads back into node state on HTML import/paste: declarative conversion entries (tag, priority, guard, per-property reads) defined beside the card's `properties` in its base node module, from which the generated node machinery derives `importDOM`. The generator throws at class-creation time when a read names an unknown property. Cards whose parsing is structural (collection payloads, sibling walking, DOM mutation, derived payloads) keep hand-written parsers.
_Avoid_: import parser, DOM conversion config

**Render context**:
The read-only, per-render-pass view of export-time policy and data that is the sole export-time view a card renderer receives besides the node: URL safety, sanitization, feature flags, color checks, document resolution, heading-id tracking, image/markdown data options, keyed export-policy resolution, render-time meta resolution. The public entry points (`exportDOM(editor, options)`, `$convertToHtmlString`, `LexicalHTMLRenderer.render`) still accept the export options and build the context from them. Card sources must not import the policy modules directly — an import guard enforces the seam. The verbatim pass-through options copy mechanically: `VERBATIM_OPTION_KEYS` (beside `createRenderContext`) is the single enumeration the factory picks from, so a new pass-through option never changes the factory body. Subsystem-specific policy does NOT join the verbatim list — it resolves through the keyed seam `resolveExportPolicy(key)` (`ExportPolicyKey` in src/nodes/base/export-dom.ts), with the deprecated flat option keys (`inklingVersion`, `footnotesSectionTitle`) forwarding as the unanswered-resolver fallback. The caption pairing invariant is single-homed beside it: `appendCardCaption` (src/nodes/base/utils/append-card-caption.ts) owns the `CARD_CAPTION_MARKER_CLASS` marker class AND the sanitized `<figcaption>` together, with the content policy as named data (`CardCaptionPolicy` — 'sanitize' default; 'escape' is video's pinned divergence, rendered through `renderCardCaptionHtml` since video is the template-string adapter). The empty-source guard is single-homed too (`hasRenderableSource` / `isSafeRenderableSource` in src/nodes/base/utils/render-empty-container.ts): a blank or URL-rejected primary source exports the empty container — the "safeUrl's `''` means unsafe" invariant is checked once, not re-derived per renderer.
_Avoid_: options bag, policy object

**Headless HTML surface**:
The public headless conversion pair-plus-one (`lexicalStateToHtml` / `htmlToLexicalState` / `lexicalStateToPlainText`, src/html/headless-html.ts) — one stateless function per direction; the export function owns the render recipe directly (there is no internal renderer class — the former pass-through was deleted and the test suites drive this seam with an injected jsdom). The shared "assemble a headless editor" recipe lives in the **headless editor factory** (src/html/headless-editor.ts) with NAMED merge modes — `additive` (renderer/plain-text: caller nodes after `DEFAULT_HTML_NODES`, last registration wins) vs `wholesale` (importer: `editorConfig` replaces the defaults) — so the deliberate node-merge asymmetry is structural, not comment-carried. Both HTML directions resolve their DOM through the headless DOM port; the plain-text direction needs no DOM and stays synchronous. The import-side surgery is single-sourced in `$insertHtmlDocument` (src/html/html-to-lexical/insert-html.ts): root reset to one scaffold paragraph, `$generateNodesFromDOM`, `@lexical/clipboard`'s `$insertGeneratedNodes` normalization (which superseded the hand-rolled facebook/lexical#2807 empty-node filter), scaffold cleanup — the headless importer and `HtmlOutputPlugin`'s initial `html` prop run the identical body.
_Avoid_: renderer class export, HTML round-trip module

**Headless DOM port**:
The only module in the package that knows jsdom (src/html/headless-dom.ts): `resolveHeadlessDom(injected?, load?)` resolves the `ExportDOMDom` for one headless conversion — an injected `options.dom` first, then the global `window.document` (mirroring the render context's createDocument chain), then a lazily imported, process-cached JSDOM, throwing an error naming the optional `jsdom` peer on failure. The jsdom loader hides behind the `load` injection port, so the failure leg is a synchronous test table. No other module may import jsdom — an import guard enforces it.
_Avoid_: jsdom imports in conversion modules, per-module DOM sniffing

**Export-time image sizing**:
The one module owning export-time img dimension policy (src/nodes/base/utils/export-image-sizing.ts): `getExportImageDimensions` returns the resized width/height when the shrink policy applies (`defaultMaxWidth` set, the intrinsic width exceeds it, and the image is local and transformable) or `null` to keep intrinsic dims. The image and gallery renderers are the two adapters; their `sizes`-attribute rules stay per-card data.
_Avoid_: resize helper, sizing logic

**Card interaction**:
The headless select→edit choreography behind InklingCardWrapper (src/plugins/behaviour/card-interaction.ts): one stable registration per card nodeKey — the editor-level CLICK_COMMAND handler (editor-level so the card can pre-empt the editor's click without blocking its own React content) and the container's mousedown select-and-swallow. Selection/edit truth is read from the card selection store at event time, so registration never re-runs per render (the former no-dep-array effect re-registered a LOW-priority command every render). Guards are data: click-through zones, the settings panel, input/textarea focus passthrough. The wrapper keeps only the render, the card-type init read (published to the subtree through CardContext's `cardType` — `useCardToolbarLabel` reads it instead of an un-subscribed render-time editor read), and the width dataset marker.
_Avoid_: click handler in the wrapper, card click choreography

**Card write seam**:
The typed write path for card-node fields: `$updateCardNode(nodeKey, guard, update)` (src/nodes/base/update-card-node.ts), called inside `editor.update()`. The card's own `$is*` guard narrows the node, so every field the mutator writes is checked against the card's node type. The React-side invocation idiom has one home beside the seam: `useCardWriter(nodeKey, guard)` (src/hooks/useCardWriter.ts) owns `editor.update` + `$updateCardNode` + the guard and returns a `write(mutator)` the card component calls per mutation — the five-line ceremony is never re-typed at a call site. Above it sits the **card chrome** prologue hook: `useCardChrome(nodeKey, guard)` (src/hooks/useCardChrome.ts) folds the trio every editable card component used to wire by hand — the editor, `write`, and `setField`, the field-writer factory (`setField('alt')` returns the `(value) => write(node => { node.alt = value })` setter, generalizing header's former private `headerFieldWriter` — kept by the header for its toggle/color-pair/blur variants). Host config is deliberately NOT folded in (plan C4): cards subscribe to the per-feature channels they actually read (`useInklingUploadSettings`, `useInklingMathSettings`, …), so one feature config's identity change re-renders only that feature's cards. Selection truth is deliberately NOT folded in: `useCardIsSelected`/`useCardIsEditing` stay the named subscription bindings, so a folded subscription never re-renders a card that doesn't read it. The bare host-uploader channel (`useMediaUploader`, src/hooks/useMediaCardUpload.ts) is the one home of the `useFileUpload` identity-stability contract — channels without input/drag/dialog wiring (video's synthesized-thumbnail sub-flow) ride it instead of re-typing the lint suppression.
_Avoid_: `$getNodeByKey` + `as GeneratedDecoratorNodeBase`

**Card selection store**:
The per-top-level-composer, editor-side store owning card-selection truth for non-React code: the selected card key and the edit-mode flag. Built on the composer handle factory; fed by registerCardSelection and the card command handlers, read synchronously by command handlers, subscribed to render-only by React via useCardSelectionState. Per-card subscriptions go through the named bindings `useCardIsSelected(nodeKey)` / `useCardIsEditing(nodeKey)` (the one home of the `selectedCardKey === nodeKey` selector shape, so the reference-equality guard's re-render granularity is decided once, never per call site); raw `useCardSelectionState` is reserved for cross-card reads (the wrapper's selectedCardKey, plugin-wide isEditingCard). There is no per-feature selection context — the former `InklingSelectedCardContext` folded into this store.
_Avoid_: selection context, selection mirror, selected-card state

**Composer handle**:
A per-top-level-composer, editor-side channel in the card-selection-store shape (getState / setState(partial) / subscribe, reference-equality change guard, render-only useSyncExternalStore binding, one provider-created instance with a module-default fallback) for values non-React code must read synchronously. One factory owns the pattern — `createComposerHandle` / `createComposerHandleBinding` (src/plugins/behaviour/composer-handle.ts, with an optional handle-subtype type parameter for channels whose handle carries methods) — and every channel is a configuration of it, never a copied store: the card selection store (above), the drag-drop handle, the word-count handle, the tk handle, and the footnote handle. Channels whose feeds rebuild record-valued state each derivation declare `recordKeys` on the factory, so a freshly built but content-equal record publish is swallowed by the one change guard instead of a hand-rolled per-handle compare (the footnote handle's indices/definitionNodeKeys are the consumer). The drag-drop handle (src/plugins/behaviour/dragDropHandle.ts) owns the editor container element, the DragDropHandler, and the isDragging flag: fed at mount by InklingComposableEditor and DragDropReorderPlugin, with the isDragging truth published by the handler itself through its `onDraggingChange` port (the owner publishes; no adapter mirrors), read synchronously by useCardDragAndDrop and useGalleryReorder — hooks register through the useDragDropContainer adapter when the handler appears instead of relying on plugin-before-children mount order — and subscribed render-only by card chrome (InklingCardWrapper, ActionToolbar) for isDragging. All five handles are created and provided by one `ComposerHandlesProvider` (src/context/ComposerHandlesProvider.tsx); React subscribes through the context bindings (`useDragDropHandleState`, `useCardSelectionState`, …) directly — the alias-hook layer is gone. The word-count handle (src/plugins/behaviour/wordCountHandle.ts) owns the top-level WordCountPlugin's onChange callback: fed at mount by that plugin, subscribed render-only by InklingNestedComposer via useWordCountCallback, which mounts a nested WordCountPlugin reactively when the callback lands instead of reading a shared ref once at render time. The tk handle (src/plugins/behaviour/tkHandle.ts) owns the per-editor TK node map plus the throttled derivation of `tkNodeMap`/`tkCount`: fed by TKPlugin's TKNode mutation listener and its unmount cleanup (`removeEditor`), read synchronously by TKPlugin's listeners, subscribed render-only by TKPlugin (indicators) and TKCountPlugin via `useTKHandleState`; its context binding is `src/context/TKHandleContext.tsx`. The footnote handle (src/plugins/behaviour/footnoteHandle.ts) owns the render-time maps the definition rows subscribe to (targetKey → 1-based visible index, targetKey → definition node key — the rows are chrome and must not walk the tree themselves) plus the focus-handoff request the caret trigger files for a freshly created definition (the row's nested editor does not exist at insert time, so the request waits for the row to mount and claim it): fed by FootnotePlugin, subscribed render-only via useFootnoteHandleState.
_Avoid_: context mutation channel, shared ref

**Reorder rules**:
The one pure module owning drag-reorder and drop-allowance decisions (src/utils/draggable/reorder-rules.ts): `resolveReorder` / `resolveDrop` / `isReorderAllowed` decide from geometry and indices alone, behind the `ReorderGeometry` seam (`createReorderGeometry(container, droppableSelector)`), so the rules carry unit tests and the DOM stays at the edges. `DragDropReorderPlugin` and `useGalleryReorder` are adapters over it — the previous third drop-allowance implementation is gone, and `insertIndex` derivation (with `adjustInsertIndexForRemoval`) lives in exactly one place. The derivation travels as the **drop resolution** (`DropResolution`, DragDropContainer.ts): `getIndicatorPosition`'s answer is kept on the handler's drag state and passed to `onDrop` as a required argument — what the indicator showed is exactly what the drop consumes, never ambient state on `DraggableInfo`; a null resolution is an explicit, typed input (the card container rejects it — no resolution, no drop; the gallery maps it to slot 0 for a container-level drop into an empty gallery). The rules decide; the drop's _application_ (relocation, insertion, source removal) lives in the drop surgery.
_Avoid_: drop logic, drag rules

**Nested-editor protocol**:
The named vocabulary for events crossing editor boundaries (src/plugins/behaviour/nested-editor-protocol.ts): `markEventFromNested` / `markEventFromCaptionEditor` tag a KeyboardEvent at the boundary, `getEventProvenance` reads the tag downstream (`NestedEditorProvenance`), and `isTypeaheadMenuOpen` is the single typeahead-open check. The protocol also owns the nested **Enter hand-off** (`registerNestedEnterHandoff`): the shared typeahead-bail / shift+enter-pass / mark + re-dispatch-to-parent + swallow core behind both nested-editor surfaces' Enter handling, with each caller's divergent branches (ctrl/cmd routing, focusNext) registered before it — the nested **blur card-reselect** (`registerNestedBlurCardReselect`): while a card's settings panel is open, blurring its nested editor reselects the parent card in the parent editor (history-merge tagged, so the reselect never lands in undo) and the panel keeps its anchor; and the caption **type-to-focus** policy (`registerCaptionTypeToFocus`): while the parent card is selected and the caption is unfocused, a printable keystroke (no modifiers, not on an input/textarea) focuses the caption editor. Consumers ask the protocol instead of reading monkey-patched flags or re-querying the typeahead menu DOM.
_Avoid_: event flag, nested-event hack

**Upload intent**:
The one media-upload flow module (src/nodes/upload-intent.ts — beside the card components that compose it): file(s) plus per-card metadata extraction in, a typed node patch out through the card write seam, and the object-URL preview lifecycle created and revoked in one place. Each media card's upload is a configuration of these primitives — per-card variance (metadata extraction, empty-result policy, pre-upload src reset) stays per-card data, never a copied skeleton; all nine intents carry per-card test tables. The video main→thumbnail composition is one flow here (`videoFlowUploadIntent` — main upload, then the synthesized `${file.name}.jpg` thumbnail sub-flow only when a url and a blob exist). The header card's background-image upload is a configuration too (`headerBackgroundUploadIntent`: pre-patch src reset, dimensions read from the result URL, empty result still patches `''`/`0`/`0`). Every metadata extraction (`getImageDimensions`, `getAudioMetadata`, `extractVideoMetadata`) is a thin config over the one **media-load wait** (`awaitMediaEvents`, src/utils/awaitMediaEvents.ts): the element's success events in — several listed events cover blob loads whose `loadedmetadata` + `canplay` arrive in one task, with `start` running after the listeners attach — error or a bounded timeout out, listeners and timer cleaned on settle; the video extractor leases its object URL from the preview-lease seam, so every settle path revokes exactly once. The React side of every media card's upload channel is the **media-card upload wiring** (`useMediaCardUpload`, src/hooks/useMediaCardUpload.ts): the host uploader for one media kind, the file drag handler, the initial-file kickoff, the insert-time dialog trigger, the hidden-input ref, and the files-only change handler — one hook per channel (audio and video compose two), with the card's intent call told which source fired (`input`/`drop`/`initial`, carrying the input-only src reset).
_Avoid_: upload handler, upload helper

**Preview lease**:
The owned lifetime of a blob object URL used as an in-editor preview (src/utils/preview-lease.ts — the one file that calls `URL.createObjectURL`/`URL.revokeObjectURL`, pinned by the upload-preview import guard): created by `createPreviewLease`, released exactly once by `release()` (idempotent), tracked in sets by `createPreviewLeasePool`, bridged to React state by `usePreviewLease`. The upload-intent module is a consumer — each intent leases its preview on start and releases it on settle. Replacing or clearing a preview releases the previous lease; unmounting releases whatever is still held.
_Avoid_: preview URL ref, object-URL ref

**Host card**:
A card the host declares through the public `defineCard` seam (src/nodes/cards/host-cards.ts) instead of the built-in declaration set: one spec (`HostCardSpec`, defined beside the registry that stores it) carries the nodeType, a `generateDecoratorNode`-built base node, the insert/menu/toolbar facts, and the decorate render, and the call returns the assembled node class to compose into `<InklingComposer nodes>` (plus the fence transformer when the spec opts into the markdown round-trip). `defineCard` validates, assembles, and registers — the registry (src/nodes/cards/host-card-registry.ts, kept registry-only so the derived views can read it without import cycles) stores the raw spec verbatim, complete at registration, and every derived view projects its own shape off it through the same projectors the built-in declarations use (the assembled class never rides the record; the views derive it through the memoized assembler). The derived views intersect with each editor's registered node types, so a host card only appears on surfaces that composed its node in. `defineCard` runs at module top level, before the composer mounts.
_Avoid_: custom card, external card

**Host config**:
The closed, per-area-sliced config a host hands `<InklingComposer cardConfig={...}>` — the exported `CardConfig` composed from `GifSettings`, `SnippetSettings`, `LinkingSettings`, `UploadSettings`, `MathSettings`, `LibrarySettings` (src/context/InklingHostIntegrationContext.tsx): gif provider keys, snippet storage callbacks, link search/embed/autocomplete hooks, image upload constraints, the math preview channel (`renderMath` — the host's server-side KaTeX render for in-editor previews; the artifacts persisted on math nodes stay host-filled, never written back by the editor), and the media library callbacks (`imageLibrary` search/upload — the image-library picker's data channel; see "Media library"). Every key the editor reads is declared; unknown keys are compile errors. Inside the editor the bag fans out by lifecycle (plan C4): `InklingHostIntegrationProvider` splits the whole value into the editor-level channel (`useInklingHostEssentials` — uploader + error sink), one context per feature slice (`useInklingGifSettings`/`useInklingLinkingSettings`/`useInklingSnippetSettings`/`useInklingUploadSettings`/`useInklingMathSettings`/`useInklingLibrarySettings`), and the drag-scroll narrow channel — each memoized on its own leaves, so one slice's identity change re-renders only that channel's consumers; `telemetry` never enters a context (see "Analytics"). The exported name stays `CardConfig` — the host-facing name the demo, docs, and internal readers already use — even though the glossary forbids "card config" as a term for card spec: this bag configures the host environment the cards run in, never an individual card's definition.
_Avoid_: options bag, card settings

**Clipboard protocol**:
The one headless module owning the paste pipeline's shared vocabulary (src/plugins/behaviour/clipboard-protocol.ts): the MIME constants, `PASTE_MARKDOWN_COMMAND`, `INSERT_MEDIA_COMMAND`, one per-editor modifier state (`getModifierState(editor)`), and input-side link acceptance. The pipeline: `registerPasteHandler.ts` (entry, `PASTE_COMMAND`) → `plainTextPaste.ts` (shared plain-text classifier) → the link leg (`PASTE_LINK_COMMAND`, already headless in `behaviour/commands.ts`, handled by `registerLinkMatching.ts`), the markdown leg (`PASTE_MARKDOWN_COMMAND` → the headless `markdownToSanitizedHtml` in `behaviour/markdownPaste.ts` → `MarkdownPastePlugin`, which keeps only the DataTransfer glue), and the file leg (`INSERT_MEDIA_COMMAND`; the drop-side claim RULES live in `behaviour/file-drop-routing.ts` — acceptable-mime derivation from the card declarations × host `fileTypes`, first-claimant-wins file matching — while the drop FLOW around them lives in `behaviour/file-drop.ts`: `handleFileDrop` behind its `FileDropPorts`, the DROP_COMMAND → `DRAG_DROP_PASTE` routing of `registerFileDropCommands` — dropped files insert at the selection left behind, never the drop point — and the dragover cursor suppression with its card carve-out in `registerDragOverSuppression`. `DRAG_DROP_PASTE` is borrowed from upstream as the public files-arrived bus (`ExternalControlPlugin.insertFiles` and hosts dispatch it) with exactly one handler, its false return letting host-registered lower-priority handlers also run; `DragDropPastePlugin` keeps only the uploader context and mounts the registration, and `CardInsertPlugin` claims per card). The protocol owns the modifier state's writes as well as its storage: the first `getModifierState(editor)` call for an editor attaches one document keydown/keyup pair writing the single `event.shiftKey` formulation (reading held-state off every key event covers the dual-shift-release corner, so it no longer exists), and the markdown leg's command listener reads the state instead of closing over React state, so Shift press/release no longer re-registers it. **Artifact slot**:
A card-node property that carries a server-prerendered artifact the editor never produces: the code card's `highlightedHtml` (Shiki HTML) and the math family's `mathml`/`svg` (KaTeX). Inkling never runs Shiki or KaTeX in the browser (CSP) — the host fills the slot on save and the node carries it opaquely through serialization; the in-editor preview stays CodeMirror (code) or the host's `renderMath` channel (math) and never writes back into the slot. The node-level invariant is **edit-invalidates**: the artifact describes the current source, so the source setters (`code`/`language` on codeblock, `tex` on math) clear the slot on change — the node-level equivalent of kobato's stripPrerenderArtifacts — while the constructor and importJSON assign the fields directly, so a host-filled artifact survives deserialization and cloning. The invariant is spec data: the source properties carry `invalidates: [...]` (the slot property names) and the generated setters enforce it; the one non-generated node (MathInlineNode) shares the same `applyArtifactSlotInvalidation` implementation. Renderers emit a non-empty artifact verbatim through the render context's named sanitize configs (`SHIKI_HTML_CONFIG` / `MATH_HTML_CONFIG`) and fall back to the escaped source when the slot is empty.
_Avoid_: prerender cache, baked preview

**Render-time meta**:

**Service machine**:

It replaces the former EventEmitter + `'drag-start-conditions-met'`/`'drag-start-canceled'` signalling, and is a port adapter over the shared **press-threshold core** (`createPressThresholdSession`, src/utils/draggable/press-threshold-session.ts — grab → movement-threshold → exactly one begin/cancel resolution, single-implemented) which it shares with the floating panel's drag session (named `createDragStartSession` to avoid the export collision).
_Avoid_: drag-start emitter, threshold promise

**Drop surgery**:
The application half of a drop (src/plugins/behaviour/drop-surgery.ts): `$relocateCard` (insertBefore/insertAfter relocation plus selection clearing), `$insertDraggedImage` (image-from-gallery insertion with node selection), `$mergeImagesIntoGallery` (image-onto-image drop — a gallery takes the target's slot with the target image first and the dragged second, the source removed), the image-card-onto-image drop policy (`isImageCardDropAllowed` + `applyImageCardDrop` — the allowance predicate and the merge application the image card's drop target delegates to), `shouldRemoveDropSource` / `$removeDropSource` (the cross-card source-removal policy), and `resolveDragMarkerRefresh` (the update-listener policy naming which dirty sets mean a top-level block was added/removed/reordered — text edits dirty only parents and skip the refresh, and Lexical 0.46's always-dirty root flag is ignored). Reorder rules decide; drop surgery applies. The gallery's list-level counterpart is the **gallery drop** module (src/utils/draggable/gallery-drop.ts): `resolveGalleryDrop` (external add with dataset→GalleryImage fill, internal reorder splice, empty-gallery slot 0) and `resolveGallerySourceRemoval` (the drag-out removal), pure transitions with the natural-size DOM read behind a probe port — `useGalleryReorder` keeps only DOM wiring, the geometry resolution, and the updateImages/refresh/result-protocol mapping. `DragDropReorderPlugin` keeps selector config, handler lifecycle, the drag-drop handle feed, and dispatch.
_Avoid_: plugin-side tree surgery, drop handler logic

**Card-menu trigger**:
The headless module owning the slash and plus menus' trigger policy (src/plugins/behaviour/card-menu-trigger.ts): one shared observe→extract→verdict loop with per-trigger resolvers — `isSlashTriggerPress` (the valid-press grammar: empty or fully-selected paragraph, no modifiers, not composing, root focused) and `registerSlashCardMenuTrigger` (query/commandParams extraction, the four close verdicts) for slash; `registerPlusCardMenuTrigger`, `resolvePlusHoverButtonVerdict` (including the left-gutter `pageX + 40` fudge — a mouse in the gutter hovers _beside_ the paragraph, so the hit-test point is nudged inward) and `shouldHidePlusButtonOnSelectionChange` for plus. Verdicts flow out (`{ query, commandParams, cursorRange }` / close; show / hide); a `null` resolution leaves state untouched. The plugins keep only their DOM event wiring, pushing verdicts into CardMenuPopup's handle; trigger policy is a synchronous test table.
_Avoid_: menu trigger effects, slash-press grammar in the plugin

**Image lifecycle**:
The image card's mount-time document-migration policies (src/plugins/behaviour/image-lifecycle.ts), headless so they are jsdom-testable (previously e2e-only inline effects): the Google-Docs `data:`-URL upload migration (`migrateImageDataUrl`), the dimension backfill for older serialized/external images (`backfillImageDimensions`), and the allowed-widths clamp (`clampImageCardWidth`). ImageNodeComponent supplies the ports (the upload channel's runner, the write seam, the error sink) and one mount effect per policy.
_Avoid_: image init effects, dimension fixups

**Upload chrome**:
The one module owning the media cards' upload visuals (src/components/ui/UploadChrome.tsx): `UploadPlaceholder` (the empty↔uploading swap over MediaPlaceholder plus the hidden input), `UploadingPanel` / `UploadingOverlay` (the empty-state and populated-state uploading visuals), `UploadFileInput` (the hidden file input), `uploadProgressStyle` (the one progress-width rule), and `useFileInputRefTunnel` (the local↔parent file-input-ref mirroring). Per-card variance is data — icon, description, mimeTypes, and `stopClickPropagation`: only the image-family sites stop click propagation, because audio/file/video enter edit mode on insert precisely via the input click propagating into the CLICK*COMMAND → EDIT_CARD_COMMAND chain. The three per-card UploadForm modules are deleted.
\_Avoid*: upload form, per-card uploading placeholder

**Header accent color**:
The one owner of the header card's color policy (src/nodes/header/header-accent-color.ts): the `accent` keyword resolution, the transparency-over-white merge (`mergeWhiteColor`), the readable-counterpart pick (`matchingHeaderTextColor`), and the async background-image resolution behind FastAverageColor (`resolveHeaderImageTextColor` — null when the policy doesn't apply: no src, the split layout, or a failed average, so the caller keeps the current color). HeaderCard keeps only the race guard and the write. The card's ~40-prop seam is narrowed to four view-model objects (`view`/`handlers`/`upload`/`editors`) that flatten inside the card.
_Avoid_: color math in the card, average-color effect

**Initial document**:
The one module owning the minimal valid Inkling document (src/utils/initial-document.ts): `MINIMAL_DOCUMENT` (the full dialect — what an empty live editor's `toJSON()` produces, `textFormat`/`textStyle` included) and `MINIMAL_DOCUMENT_LEGACY_PAYLOAD` (the historical dialect without them — `importJSON` treats the fields as optional, so stored host payloads stay valid; the dialects' relationship is pinned by test), `$appendEmptyParagraph` (the live empty-root repair), and `normalizeInitialEditorState` (the serialized empty-root repair, legacy dialect). `htmlToLexical`, `nested-editors`, `generateEditorState`, and the InklingComposer bootstrap are adapters. The module also carries the transform-policy note: the public import path's denest/merge/alignment transforms are registered on a one-shot headless editor, while `generateEditorState` populates long-lived nested editors where a persistent transform would re-run on every later edit — the divergence is deliberate.
_Avoid_: empty-document literal, blank editor state

**Gif browser**:
The headless module owning the gif picker's behaviour (src/utils/services/gif-browser.ts): `createGifBrowser({ config, fetchPage?, scheduler? })` publishes a snapshot (`gifs` / `columns` / `highlightedId` / `isLoading` / `isLazyLoading` / `error`) and accepts intents (`search`, `load-more`, `set-column-count`, `highlight`, `select`, `key`) via `dispatch`, which returns one-shot DOM effects (prevent-default, focus-search, insert) for the adapter to execute. Fetch and pagination sit behind the fetch port with a latest-wins race guard; column balancing and keyboard navigation are pure transitions (`reduceGifKey`) with `elementFromPoint` probing behind a per-dispatch geometry port, so navigation is a synchronous test table. `useGifBrowser` (src/hooks/useGifBrowser.ts) is the thin React adapter; `GifSelector` renders and dispatches intents. It replaces `useGif`'s refs-plus-state double mirroring and unblocks the recorded tile-focus a11y rework.
_Avoid_: gif hook, selector navigation logic

**Gallery images mirror**:
The one module owning the gallery card's node↔state sync (src/hooks/gallery-images-mirror.ts): `createGalleryImagesMirror(ports)` — node images in through `readNodeImages` / `subscribeToNodeImages`, the rendered list out as a reference-stable snapshot, `setImages` for local-mutation-plus-node-write, `setPreviewImages` for the local-only preview overlay that never touches the node. External node changes (undo, collab) replace the overlay wholesale; the echo of the mirror's own write is detected by persisted-props comparison so in-flight previews survive a mid-upload reorder. `useGalleryImages` (src/hooks/useGalleryImages.ts) is the React adapter — `registerUpdateListener` filtered on the gallery node, writes through the card write seam — and the upload-intent gallery adapter publishes previews through `setPreviewImages`, preserving preview-first ordering. It closes the within-card-undo stale-list bug, where a mounted card kept rendering the old list and wrote it back on the next interaction.
_Avoid_: gallery local state, node-state mirror

**Labels**:
The closed, flat table of every user-visible string the editor chrome renders (src/labels/inkling-labels.ts) — dotted keys (`placeholder.editor`, `menu.image.label`, `action.delete`) with English defaults in `DEFAULT_LABELS`, merged once per composer from the host's partial override table (`<InklingComposer labels={...}>`, `InklingLabelsInput`) into `InklingUiPrefsContext.labels`, and read by components through `useInklingLabels()`. The interface is closed — an unknown override key is a compile error (the host-config closed-bag philosophy) — and interpolation rides one typed seam beside the lookup (`interpolateLabel(text, { max, cardType, name, progress })` — plain `string.replace` underneath, never an i18n library; the token set is a compile error to mistype). Menu labels are the one indirection: each card declaration's menu entry carries a required `labelKey` beside its English `label`/`desc`, and `buildCardMenu` resolves `menu.${labelKey}.label`/`.desc` at menu-build time through the resolver `useCardMenu` injects from the context — the declared English is the fallback an unresolvable `labelKey` (e.g. a host card's own key) renders. Host cards carry the same required `labelKey`, so the seam is uniform across built-in and host declarations. The Pintura editor is the one nested third-party consumer: the table's `pintura.*` keys feed its `locale` first and `cardConfig.pinturaConfig.locale` spreads on top (the merge lives in `buildPinturaOptions` in the **Pintura session**, src/utils/services/pintura-session.ts — the integration's one headless home: the asset loader behind DOM ports with a request-track guard, the options table, and the close gate; `usePinturaEditor` is the thin adapter). Export-renderer strings (video/toggle aria) and host data (snippet names) stay outside the table by design. The full key list is the contract — `test/unit/labels.test.ts` snapshots it, and `src/labels/inkling-labels.ts` is the host-facing reference.
_Avoid_: i18n, translations, locale strings

**Media library**:
The host-driven image-library picker seam. The `LibrarySettings` slice of the host config carries one key, `imageLibrary`: a `search` callback (empty query = the default listing, fired immediately on open; non-empty queries debounced at 300ms; `undefined` resolves like a cancellation and keeps the last items) and an optional `upload` callback (the host owns the whole upload UX; its resolution is treated as the selection, `undefined` = cancelled). Open/close state fully reuses the gif picker's transient `selector` overlay mechanism: the image declaration's "Image library" menu entry (gated on the config's presence via `isHidden`) dispatches `OPEN_IMAGE_LIBRARY_COMMAND`, which inserts a placeholder image node carrying `__selector: LibraryPlugin` + `__isImageHidden` — the overlay is open while that node exists; Escape/click-outside dispatch `DELETE_CARD_COMMAND` and the document keeps no trace. The placeholder lifecycle (Escape/click-outside delete, the async-pick placeholder-exists guard) has one owner shared by the gif and library plugins (`useSelectorPlaceholderLifecycle`, src/hooks/useSelectorPlaceholderLifecycle.ts). A pick maps the item through `toImageDataset` — the flow's only field-mapping point, living in `LibraryPlugin` — and dispatches `INSERT_FROM_LIBRARY_COMMAND`, which shares one insert surgery with `INSERT_FROM_GIF_COMMAND` in `src/plugins/behaviour/selector-insertion.ts` (build the card from the dataset, `INSERT_CARD_COMMAND`, remove the placeholder — the **selector insertion** module, a synchronous test table); both commands keep their own names for menu/analytics semantics. The headless `createLibraryBrowser<TItem>` state machine (src/utils/services/library-browser.ts — single request track, latest-wins race guard, a rejection keeps the last items and sets `error`; deliberately no pagination, keyboard-navigation machine, or column balancing) is generic over the item shape and exported from both published entries so a host's own library pickers (e.g. music on a host card) reuse it; `useLibraryBrowser` is the thin React adapter and `LibrarySelector` the image-shaped render shell (internal — square tiles with a dims badge, optional upload button, built-in click-outside). The three host-schema keys (`thumbhash`/`storagePath`/`imageId`) ride the image dataset's open index signature as opaque pass-through data: the stock image declaration silently ignores them, and they persist only when the host declares them as properties on its own card declaration. Save-time re-sync against the library (re-resolving fields, writing alt back) is host server logic by design — the editor's responsibility ends at carrying the keys faithfully into the serialized state.
_Avoid_: media manager, asset picker

**External control**:
The headless host-facing control surgeries behind `ExternalControlPlugin` (src/plugins/behaviour/external-control.ts): `focusEditorAt` (focus at a document end, with the decorator-node selection dance Lexical does not do itself), `insertParagraphAt` (paragraph at either document end), and `lastNodeIsDecorator`. The plugin is API assembly only; hosts drive the same flows without a React mount.
_Avoid_: editor API plugin, host controls

**Table facts**:
The one owner of the table family's "header row only, never a header column" invariant as export policy (src/nodes/table/table-facts.ts): the HTML direction reads the cells' header state (`getTableCellTag` — a header cell is a `<th>`, so a headerless table stays headerless), while the GFM markdown direction FORGES row 0 as the header (`resolveGfmPipeTableLines` — GFM has no headerless tables). The divergence is declared in one module instead of re-derived per export transformer; the insert command owns the construction default (3×3 with header row) in the behaviour layer.
_Avoid_: header-row logic per transformer

**Paragraph restriction**:
The RootNode invariant behind `RestrictContentPlugin` (the `./core` comment-level composition's "paragraphs only" mode): decorator cards are stripped, list nodes unwrap to their items' paragraphs, non-paragraph top-level nodes convert to paragraphs, the document truncates to `paragraphs`, and the selection repairs to the document end. The policy is headless — `$enforceParagraphRestriction(rootNode, paragraphs)` in src/plugins/behaviour/restrict-content.ts, a synchronous test table — and so is its registration: `registerParagraphRestriction` (same module, mirroring `registerTableCellGuard`) owns the transform and the `isEditorUpdating` guard; the plugin keeps only the HIGH-priority paste wiring. Same genus as the table cell guard and the footnote doc-end-run invariant, but deliberately NOT a default transform — the headless import path does not enforce it. The genus' shared "only install when the node class is present" gate is `registerNodeTransformIfPresent` (src/transforms/register-node-transform.ts): default transforms run against varying node sets, so denest/merge-list-nodes/remove-alignment/table-cell-guard all install through it — a member that forgets the gate crashes `./core`-style surfaces.
_Avoid_: content filter, paragraph-only mode

**TK indicator**:
The headless module owning the TK indicator's geometry and cycle policy (src/plugins/behaviour/tk-indicator.ts): `resolveTkIndicatorPosition(rootRect, positioningRect)` — the base offsets (`TK_INDICATOR_BASE_RIGHT` / `TK_INDICATOR_TOP_OFFSET`, the former magic −56/+4) plus the strict overflow-right adjustment, rects as plain data behind the same rects-as-data pattern as the selection-anchored popup and the drop indicator — and `nextTkNodeKey(nodeKeys, currentKey)`, the click-to-cycle transition (next in document order, wrap at end, unknown key selects first). The TK node bookkeeping lives beside it in `src/plugins/behaviour/tk-tracking.ts`: `registerTkNodeTracking` (the mutation-listener → tk-handle feed) and `applyTkHoverHighlight` (the classList swap, a no-op under a card parent). `TKPlugin` measures, renders, and keeps the portal; the math and the feeds are synchronous test tables.
_Avoid_: tk positioning logic, indicator math in the plugin

**Telemetry channel**:
The one analytics seam (src/utils/analytics.ts): `trackEvent(eventName, props)` is the only call components and behaviour modules make, and the handler behind it is host-swappable — `setTelemetryHandler(custom)` installs a handler and returns a restore teardown, with the default fanning out to the plausible/posthog window globals when they exist. The host config carries the handler on its `telemetry` key and `InklingComposerBase` wires it through an effect (nested composers don't re-wire). The channel is page-global by design: two editors on one page share one analytics identity, so the seam is process-wide rather than a per-composer context.
_Avoid_: analytics calls, trackEvent wrappers

**Scroll ancestor**:
The one scroll-container front door (src/utils/scroll-ancestor.ts): `getScrollAncestor(node, policy)` with two named policies — `'floating'` (walk up for the nearest scrollable ancestor, falling back to the document scrolling element; the floating UI and selection-anchored popups' reposition container) and `'drag-scroll'` (delegates to the vendor-synced `getParentScrollableElement` in draggable-utils, which mirrors inkling-card-gallery and must not be restructured). The drag-scroll container is host-overridable through the composer's `dragScrollContainerSelector` prop, which rides its own narrow host-integration channel (`useInklingDragScrollContainerSelector`) into `DragDropReorderPlugin`'s ScrollHandler options; the library default bakes in no host class.
_Avoid_: scroll parent, getScrollParent

**Utils layer**:
The bottom layer of the module graph (src/utils/): framework-free helpers the upper layers (nodes, components, hooks, plugins) pull in, never the reverse. Node-coupled modules live with their consumers instead — the upload intents beside the card components (src/nodes/upload-intent.ts), the menu build and the registered-cards projection in the card pipeline (src/nodes/cards/card-menu-build.ts, src/nodes/cards/editor-card-nodes.ts), the nested-editor bootstrap beside MINIMAL_NODES (src/nodes/nested-editors.ts), the image width policy beside the width vocabulary (src/nodes/base/utils/image-card-widths.ts), the bookmark embed flow beside its hook (src/hooks/bookmark-embed-flow.ts). The boundary is structural, not comment-carried: test/unit/utils/utils-import-guard.test.ts fails CI when a utils module runtime-imports `@/nodes` (except the pure leaf helpers under `@/nodes/base/utils/`, which both trees share), `@/components`, `@/hooks`, or `@/plugins`; type-only imports erase at runtime and stay free. `CARD_WIDTHS` reaches the public barrel through exactly one re-export (src/utils/index.ts).
_Avoid_: helpers dump, shared kitchen-sink
