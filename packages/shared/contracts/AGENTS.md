# `@kobato/contracts`

The wire layer — everything that crosses a transport or a package boundary as data. Owner of: the per-domain Zod schemas + derived DTOs (`content`, `admin`, `posts`, `pages`, `comments`, `users`, `images`, `analytics`, `notifications`, `observability`, `trace*`, …), `api-error` (`ErrorMessageDescriptor` / `ErrorIssueWire` / `ApiErrorData` — producers state a typed id, the server translates per request, every issue carries BOTH the display `message` and the descriptor), `primitives` (the shared Zod primitives — `idString` / `isoDateTime` / `markdownHeadingDto` — that the per-domain schemas compose; the `Assert`/`Equals` type-level helpers live in `@kobato/utils/type-equals`), `catalog` (the public read-model domain: the `Post`/`Page`/`ClientPost`/`ListingPostCard`/shell/`Friend` read shapes and their runtime projections `toClientPost` / `toListingPostCard` / `toDetailPostShell` / `toDetailPageShell` / `toSidebarPostLink` — a cohesive domain at the contracts root, not a loose types bucket), `merge-patch` (the shared contract for multi-column field-update procedures: `mergePatchInput` / `clearable` / `splitMergePatch`; the users domain is its current production consumer — adopt it for new field-update procedures, don't cite it as broader precedent than that), `constants/route-warmup` (the sentinel, manifest types, and exclusion patterns shared by the build plugin and the client idle script), `sea/assets` (the SEA embedded-asset key contract — single owner for the writer in `@kobato/pack` and the runtime readers in the server), and `types/` (`backup`, `comments`, `listing`, `sessions` — the remaining cross-boundary shapes with no full schema).

- Allowed deps: `@kobato/settings`, `@kobato/i18n`, `@kobato/utils`, `@kobato/lexical`, `@kobato/assets`, `@kobato/cache`. Nothing product-side; nothing imports "back down" — db/server/ui/web import contracts, never the reverse.
- Zod DTO single source: each wire DTO is declared once as a Zod schema; its TS type derives in the same module (`z.infer`). No hand-written DTO twins — consumers `import type` from the owning contracts module. Exception: the content/admin SSR output schemas use `z.custom<T>()` over the loader-data types (bit-identical SSR rendering; input schemas and the redirect/not-modified unions stay real Zod) — scoped to `content.ts` + `admin.ts` only. `MetaDescriptor` arrives as an erased react-router `import type` (not a React import).
- Tests: `tests/unit/` — including the SEA contract tests that textually pin the `@kobato/pack` sources (umbrella `shared-unit` project — see `packages/shared/tests/AGENTS.md`).
