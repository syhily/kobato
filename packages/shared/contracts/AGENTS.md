# `@kobato/contracts`

The wire layer — everything that crosses a transport or a package boundary as data. Owner of: the per-domain Zod schemas + derived DTOs (`content`, `posts`, `pages`, `comments`, `likes`, `users` (incl. the whole `account.*` family), `images`, `analytics`, `settings` (the admin settings RPC envelope), `notifications`, `observability`, `backup`, `sessions`, `webmentions`, …), `api-error` (`ErrorMessageDescriptor` / `ErrorIssueWire` / `ApiErrorData` — producers state a typed id, the server translates per request, every issue carries BOTH the display `message` and the descriptor; also owns `zodIssueParams`, the ONE issue-params extractor for the numeric bounds + custom `params` bag), `primitives` (the shared Zod primitives — `idString` / `isoDateTime` / `markdownHeadingDto` / `safeBoolean` / `honeypotField` — that the per-domain schemas compose; the `Assert`/`Equals` type-level helpers live in `@kobato/utils/type-equals`), and `merge-patch` (the shared contract for multi-column field-update procedures: `mergePatchInput` / `clearable` / `splitMergePatch`; the users domain is its current production consumer — adopt it for new field-update procedures, don't cite it as broader precedent than that). The `likes` wire family is the schema single source the `@kobato/api` likes contract composes.

`comments.ts` is the single comments wire owner: the public/admin comment Zod DTOs, the comment-entity parse/serialize pair, the comment oRPC input/output interfaces, and the `Comments` `{ count, roots_count }` summary the public React reads (PII-heavy admin rows keep their server-side model in `@kobato/server/domains/comments/types.ts`; the parity assert lives in the server's `projection.ts`). `backup.ts` and `sessions.ts` hold the cross-boundary shapes that graduated from the former `types/` bucket.

Moved out (do not move back): the public read model (`catalog` + `types/listing`) → `@kobato/catalog`; `constants/route-warmup` and `sea/assets` → `@kobato/distribution`; the `trace*` observability protocol → `@kobato/telemetry`.

- `content-admin-base.ts` is the post/page admin wire base (`upsertMetaBaseSchema`, `adminMetaBaseDto`, `slugSchema`, `contentLanguageField`) that `posts.ts`/`pages.ts` extend. It is content-specific, not a `primitives.ts` candidate: `primitives.ts` holds only schemas with no single domain owner.
- A UI-only helper never lives here, even when it is pure: random pickers, tab groupings, and display derivation belong to the consuming web leaf (`pickEmptyStateLineId` → `@kobato/web-admin/ui/dashboard/empty-state-lines.ts`).
- Allowed deps: `@kobato/auth`, `@kobato/catalog`, `@kobato/settings`, `@kobato/i18n`, `@kobato/utils`, `@kobato/inkling` (headless — the document schemas), `@kobato/assets`, `@kobato/cache`. Nothing product-side; nothing imports "back down" — db/server/ui/web import contracts, never the reverse.
- Zod DTO single source: each wire DTO is declared once as a Zod schema; its TS type derives in the same module (`z.infer`). No hand-written DTO twins — consumers `import type` from the owning contracts module (`BackupFileDto` is the canonical backup example). Exception: the SSR output schemas use `z.custom<T>()` over the loader-data types (bit-identical SSR rendering; input schemas and the redirect/not-modified unions stay real Zod) — scoped to `content.ts` and the per-domain admin families that landed with the former `admin.ts` grab-bag (now dissolved into `users`/`comments`/`analytics`/`posts`/`webmentions`/`settings`). `MetaDescriptor` arrives as an erased react-router `import type` (not a React import).
- Tests: `tests/unit/` — including the schema/primitives and `zodIssueParams` suites (umbrella `shared-unit` project — see `packages/shared/tests/AGENTS.md`). The SEA contract tests moved with `@kobato/distribution`.
