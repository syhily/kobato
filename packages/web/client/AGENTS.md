# Web-client conventions

`@kobato/web-client` (`packages/web/client/`) is the browser platform layer: document-level hooks, the oRPC client, the root settings contexts, route warmup, and the cross-surface editor platform. It may import the shared leaves it declares (`@kobato/{utils,i18n,settings,telemetry,distribution,contracts}`), `@kobato/api`, `@kobato/ui`, `@kobato/inkling`, and sibling modules through `@kobato/web-client/*`. It must NOT import `@kobato/web-admin` or `@kobato/web-public` (the direction is strictly product leaves → `@kobato/web-client`; a client module that needs a product component moves up to that leaf) and must NOT import `@kobato/server` or use Node-only APIs — the oRPC client is typed exclusively through `ContractRouterClient<typeof apiContract>` from `@kobato/api`.

## Structure

- `hooks/` — the seven document-level hooks, each mounted once per document: `use-rum`, `use-rum-consent`, `use-device-env-beacon` (one `sendBeacon` per page view, DNT honored, no fetch fallback), `use-ios-no-zoom`, `use-chunk-error-recovery`, `use-detach-public-css`, `use-focus-hash`. Product-level hooks live in the product leaves.
- `use-rum`: mounted once by the root `App`, renders no DOM, runs only in an effect. It returns before the dynamic import when the root loader supplied no bootstrap (frontend RUM not configured or the O2 pipeline gate withheld it), when DNT/GPC deny, or when the bootstrap fails the strict schema — a denied/disabled browser never downloads the SDK chunk. A `clientIdentity: 'forward'` bootstrap adds the strict consent gate (`lib/rum-consent`, localStorage `kobato.rum.consent`); `declined` fully stops a running SDK, and the root `App` renders `RumConsentBanner` only post-mount, only while undecided, never for DNT/GPC visitors.
- The root bootstrap is emitted in EVERY build once the server-side OpenObserve pipeline verification gate passes. The effect's `import.meta.env.SSR` early return removes the dynamic-import edge from the server graph. It forwards a `{ id, template }` route identity and nothing else — no pathname, search, params, or title.
- `lib/` — pure browser helpers (`motion`, `chunk-error`, `device-env`, `locale-sync`, `viewport-zoom-lock`); the RUM family lives in `lib/rum/`.
- `lib/rum/openobserve-rum.ts` is the ONE client SDK entry: it dynamically imports `@openobserve/browser-rum-slim` after the gate and points the SDK's `proxy` URL builder at the same-origin `/api/rum/intake` relay — the OpenObserve endpoint/organization never reach the browser, and the mandatory `clientToken` is a placeholder the server relay swaps for the real one. Init: interactions off, Replay/telemetry/profiling rates 0, `defaultPrivacyLevel: 'mask'`, no anonymous user; `allowedTracingUrls` is a same-origin predicate only. `startRum` is idempotent and never throws.
- `rum-sanitizer.ts` is the pure, synchronous `beforeSend` allowlist: it builds a NEW event; unknown shapes, unrecognized URLs, and any thrown error drop the event. The slim SDK's `limitModification` copies only declared paths back, and ignores `false` for `view` — the sanitizer overwrites the view's free fields with the trusted route BEFORE any risky work; `error.stack` is always overwritten. The OpenObserve ingest pipeline in `tools/trace/src/` is the authoritative fail-closed boundary — run `trace:init` before enabling frontend RUM.
- Status polling: `openobserve-rum.ts` polls the no-store `/api/rum/status` every 10s; false/error calls `setTrackingConsent('not-granted')`, recovery restores `granted` and calls `startView(current route id)` in the same document (an open editor's unsaved input is preserved). A null bootstrap calls `suspendRum()` (keeps the handle + poll for recovery); DNT/GPC, an invalid bootstrap, and a real unmount call `stopRum()`. `rum-url-policy.ts` is the single telemetry-exclusion predicate; `rum-budget.ts` owns the 500 resources / 100 errors session cap.
- `device-env` reads every browser API defensively — an absent/non-finite value is omitted, never sent as null.
- `locale-sync` is the cross-tab settings-locale transport: a `BroadcastChannel` announcement plus a subscription. It carries an ANNOUNCEMENT, not state — peers reload from the server after flushing their own dirty cards and never re-publish; the ROOT-level `LocaleSyncProvider` (mounted in `src/root.tsx`) owns the subscription. Only a registered settings workspace flushes and reloads automatically; every other document shows a localized notice with an explicit Reload. A missing/blocked API degrades to a no-op.
- `settings/blog-settings-context.tsx` — one context per section (never one bundle context), so a save to one section never invalidates subscribers of another. Adding a section = create the context and register it in `SECTION_CONTEXTS_ANY`.
- `route-warmup/` — `RouteWarmupScript` renders the inline idle-preload script; the manifest contract lives in `@kobato/distribution/warmup-manifest`, the wire constants in `@kobato/distribution/route-warmup`; client code reads only the shared constants.
- `editor/` — the cross-surface editor platform both composers share: `editor-surface` (`useEditorSurface` + `EditorSurfaceComposer`, the InklingComposer shell with active-locale labels, word-count language, and darkMode; every delta passes through, `nodes` stays required), `base-node-filter`, `block-quote-aside-cycle`, `use-editor-body-reset`, `inkling-labels`. The page composer is consumed by `@kobato/web-admin/ui/editor/PageBodyEditor`, the comment composer by `@kobato/web-public/ui/comments/CommentBodyEditor` — each surface's node set, host cards, uploads, pickers, and copy live beside its consumer.
- `inkling-labels` is the client seam for the Inkling label overlay — the four per-locale tables stay out of the browser's static graph. WORKSPACE documents read the root loader's `i18n.inklingLabels` payload; PUBLIC documents `loadInklingLabels(locale)` — the ONE sanctioned dynamic import of a table module; hover/focus intent prefetches that chunk together with the composer chunk. Four locales are four chunks, never one; no static table import is allowed anywhere in the client.
- `api/` — oRPC client. All RPC calls go through `orpc.<domain>.<endpoint>(flatInput)` from `@kobato/web-client/api/client`; errors arrive as `ORPCError` rejections whose `message` already carries the request-locale issue summary, with `{ descriptor, issues }` in `data` (the client never inspects `data` for copy and installs no rejection interceptor). TanStack Query wrappers live in `api/orpc-query`. Every public-site read flows through oRPC end to end — browser interactions use this client, SSR goes through the in-process `content.*` caller; no route talks to domain services directly.

## Patterns

- All interactivity lives in React hooks/components — platform glue here, product components in the leaves. The one non-React script is the route-warmup idle loader, generated through the build-time virtual module.
- Interactive components call resource URLs through the oRPC client; the `@kobato/api` contract is the only RPC type channel.
- Heavy widgets reach the bundle via React.lazy + Suspense, not top-level imports. Avoid new client deps unless the interaction needs them.

## iOS auto-zoom

- iOS Safari zooms in when focusing a control with `font-size < 16px`; the zoom is decided when the TAP'S DEFAULT ACTION focuses the target — rewriting the viewport `<meta>` from `focusin` is too late.
- The lock is refcounted in `lib/viewport-zoom-lock` (iOS/iPadOS WebKit only): every activation that ends in a focus holds the lock BEFORE focus lands, then releases. `useIosNoZoomOnFocus()` is mounted once at the top of the root `App`: `pointerdown` in the CAPTURE phase acquires it, form controls keep it for their whole focused session, a contenteditable canvas releases on the task after its focus lands. The comment composer's activation handoff holds the same lock from the activating tap until one task after the contenteditable takes focus.
- Do NOT re-install the hook per-form and do NOT rewrite the viewport `<meta>` anywhere else — both race the same refcount.
