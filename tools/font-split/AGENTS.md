# @kobato/font-split

Vendored fork of [KonghaYao/cn-font-split](https://github.com/KonghaYao/cn-font-split) (Apache-2.0, `release` branch @
`1650af13` — upstream's `chore: 7.4.3`, the last release-branch commit before the 8.0 work; the `7.6.8` tag and GitHub
release sit on another upstream line and only name the wasm package `BENCHMARK.md` measures) rebuilt as a Node-API
native addon, with two upstream 8.0 fixes ported by hand: the shaping-relation collection rewrite (`7cb5fcc`) and the
order-stable cmap reverse lookup (`7e6d720`). The product consumes it ONLY through
`nativeRequire('@kobato/font-split/font-split.node')` (`packages/server/src/infra/sea/native-require.ts`) — product src
never statically imports this package, so the tools boundary in `package-dag.test.ts` is untouched. The root
`package.json` declares it as a production dependency per the "native-dynamic-library at runtime lives in ROOT
dependencies" convention. Measured results — the λ frontier, page cost, shaping co-location, rendering, loading time,
slicing time and build profile — live in `BENCHMARK.md`; the design rationale and its revisions live in
[ADR-0010](../../docs/adr/0010-frequency-ordered-byte-aware-font-slicing.md). `BENCHMARK.md`, the `benchmark/` charts
and `benchmark/results.json` are GENERATED by `pnpm run bench:font-split` (`tools/font-split/scripts/bench/`): rerun it
after an algorithm change instead of editing numbers — only the prose outside the `<!-- bench:start … -->` markers is
hand-written.

## Layout

ONE Rust crate (`kobato-font-split`, cdylib + rlib at the package root) — the upstream multi-crate workspace was merged:

- `src/` — the slicing core (upstream root crate): `pre_subset/` → `run_subset.rs` → `link_subset/` (result.css), plus
  the upstream helper crates as modules: `utils.rs` (cn-font-utils), `unicode/` (unicode-range + lang_unicodes merged:
  `range.rs` = UnicodeRange, `mod.rs` = script areas, `cjk.rs` = tables + touch probabilities + algorithm fingerprint).
  Protobuf fully removed: `src/config.rs` (`FontSplitConfig`/`CssProperties`) replaces `InputTemplate`, `src/output.rs`
  (`OutputFile`) replaces `EventMessage`; `font_split(config, callback)` is the only entry and returns the warnings of
  the run.
- `src/pre_subset/` — the partition pipeline, one plugin per stage in a fixed order:
  - `plugins.rs` — language-area packs, then the remainder pack. A pack's language tag is pushed next to it
    (`PreSubsetContext::subset_languages`, position-aligned with the subsets) and every plugin keeps the two aligned;
    the tag selects the DP byte cap (`auto_chunk::cap_bytes`), never a position lookup.
  - `auto_chunk.rs` — the DP chunker, run per pack. Each pack is probed with a strided sample of ≈100 characters
    (`sample_of`), compressed at woff2 quality 9 (`PROBE_QUALITY`, ≈27× cheaper than the shipped quality on the same
    faces). The probes are rescaled to shipped bytes with one quality-9/quality-11 pair on a pooled sample of ≈120
    characters drawn from every pack (`reference_share` / `take_share`, `probe_scale`): the q11/q9 ratio is a font-level
    constant (within ±1% for 80% of faces), so it replaces a quality-11 probe per pack, which cost +25% slicing time,
    and costs no more than the old font-wide quality-11 sample. On the fixture font this reproduces the per-pack
    quality-11 output byte for byte. `dp_split_by_prob` minimizes `Σ P(touched)·(bytes+λ)+μ` under the pack's cap
    (`tests/auto_chunk.rs`). One global bytes/char must not come back: it overstated Latin, symbol and punctuation packs
    ≈5× and cut them into more faces than their bytes justify (28 → 17 non-Han faces on the production font; ADR-0010,
    2026-11-26 revision). `pre_subset::predict_bytes` rejects `chunk_size <= 0` instead of slicing one character per
    face.
- `src/run_subset.rs` — subsetting + WOFF2 compression at `WOFF2_QUALITY` (11), read through `woff2_quality()` so the
  pooled probe reference and the faces always agree. Under the `bench` feature two environment seams serve the
  slicing-time benchmark and never reach the addon: `FONT_SPLIT_BENCH_WOFF2_QUALITY=<n>` replaces the shipped quality,
  `FONT_SPLIT_BENCH_SKIP_COMPRESSION=1` emits the raw subset instead of a WOFF2.
  - `features.rs` — the shaping closure, run AFTER chunking: every GSUB/GPOS relation is hoisted whole into the first
    intersecting subset. `features/opentype.rs` holds the shared reading primitives — Extension lookups (GSUB type 7 /
    GPOS type 9) are expanded up to `MAX_EXTENSION_DEPTH`, pair adjustments contribute both sides, ligatures their first
    component — and `cmap.rs` injects the glyph → codepoint reverse lookup in descending codepoint order, so a glyph
    mapped from several codepoints resolves deterministically. A table `opentype` cannot read is reported as a
    `TableError` (`features/opentype.rs`: table, offset, size, cause): an unreadable cmap is still a rejection, an
    unreadable GSUB or GPOS is a warning — the slice proceeds without that table's relations. The `log` crate is
    installed nowhere in the addon, so its records are tracing only: whatever a consumer must see travels in the
    result's `warnings`. Combining marks are deliberately NOT copied into every subset (upstream 8.0 `5cdc0ae`): +14%
    package bytes on the production font for no page-cost gain, and it breaks the exactly-once coverage invariant of
    `chunk_integrity.rs` / `page_cost.rs`.
- `src/unicode/cjk_tables.rs` — @generated CJK priority tables (Kobato-owned, replacing the upstream OpenCC-derived
  data; each vendored list's provenance lives in `scripts/cjk-tables/`). Regenerate with `pnpm run corpus:generate` from
  the official character lists plus the committed corpus frequency TSVs `freq-zhwiki-20261101-{hans,hant}.tsv` (produced
  by `corpus build`). Pack MEMBERSHIP is exactly the official lists; the ORDER inside each pack is corpus
  document-frequency, carried per character by the `*_DF` arrays the DP chunker consumes as touch probabilities. The
  subsets carry tags `ZH_SC_1/2/3`, `ZH_HK`, `ZH_TW`, `ZH_JA`.
- `src/binding.rs` — the napi-rs binding (upstream `ffi-js` reimplemented). `fontSplit(input, options?)` returns a
  Promise of `{ files, warnings }` (napi `Task`/`AsyncTask` on the libuv pool; core rayon parallelism unchanged). Core
  panics are caught and rethrown as JS errors. napi-rs 3 with the `napi10` feature (Node-API v10, the Node 26 baseline);
  options arrive as a `#[napi(object)]` camelCase struct.
- `build.rs` — `napi_build::setup()` plus one compile-time env, `OUTPUT_DEP_VERSIONS`: the `Cargo.lock` versions of the
  two dependencies that shape output bytes (`harfbuzz_rs_now`, `woff`), hashed into the algorithm fingerprint so a
  dependency upgrade can never reuse stale slice keys. No data is generated at build time (the upstream
  `lang_unicodes/build.rs` data generation, incl. the opencc-rs/cmake chain, is gone).
- `src/binding.d.ts` — @generated by `napi build` from the `binding.rs` macros (the `--dts` flag): the single source of
  truth for the addon's TS types, committed and exported as `@kobato/font-split/binding`. Regenerated on every build —
  never hand-edit; the header (pinned via `napi.dtsHeader` in `package.json`) carries the `oxlint-disable` /
  `oxfmt-ignore` opt-outs itself, so the root lint/format configs need no ignorePatterns entry.
- `src/index.ts` — thin wrapper typed from `src/binding.d.ts` (no hand-written type mirror): `fontSplit` /
  `fontSplitAlgorithmVersion` pass the native signatures through, lazy-loading `font-split.node` with an actionable
  error when missing. It and the generated `binding.d.ts` are the only TS here; `tsconfig.json` is the standard package
  shape. `src/` carries no tooling: the local-only tooling is TypeScript under `scripts/`.
- `font-split.node` (package root, gitignored) — the addon binary, built and placed by `@napi-rs/cli`
  (`napi build --release --output-dir .`); the stable specifier both `nativeRequire` and SEA staging rely on. The file
  name comes from `napi.binaryName` in `package.json`. The CLI always compiles with `--target <host triple>`, so cargo
  intermediates land in `target/<triple>/release/`. The release profile is fat LTO + `codegen-units = 1` +
  `strip = "symbols"` (BENCHMARK.md: −22% addon size, a slicing-time difference inside the run-to-run noise).
- `scripts/` — the local-only TypeScript tooling (`node scripts/<entry>.ts` under type stripping; never bundled, never
  run in CI). The modules import each other as `@kobato/font-split/scripts/*` (the package export maps it onto
  `scripts/*.ts`) and are tested under `tests/unit/scripts/`.
  - `scripts/gen-cjk-tables.ts` — regenerates `src/unicode/cjk_tables.rs` from the vendored lists and the frequency TSVs
    in `scripts/cjk-tables/`: membership is the official lists, the order inside a pack is corpus document frequency
    (carried by the `*_DF` arrays), the official table sizes are enforced, and the string literals are rendered exactly
    like Rust's `{:?}`.
  - `scripts/corpus.ts` — the corpus CLI: `download` (the pinned zhwiki dump into gitignored `.cache/` through
    `curl -C -`, skipped once the file has the remote size), `build [--workers <n>]` (one streaming pass over
    `bzip2 -dc`: wikitext clean → OpenCC t2s/s2t through the vendored dictionaries in a worker pool → per-dimension
    character document frequencies → `scripts/cjk-tables/freq-zhwiki-20261101-{hans,hant}.tsv`, held-out page fixtures →
    `tests/fixtures/pages/zh-{hans,hant}-heldout-64.txt` with fixture pages EXCLUDED from the counts), `generate` (the
    same generator) and `blog-pages <kobato.db> <out>` (the production-blog page fixture: the published post/page bodies
    of a Kobato content database, opened read-only through `node:sqlite`, projected to the codepoints the public theme
    renders in the post font slot — text outside `pre`/`code`, form controls, svg and MathML, plus ordered-list markers,
    stored as codepoint sets only; fails on any entity or tag shape it does not model).
  - `scripts/corpus/` — one module per stage: `profile.ts` (the dump pin, the fixture rule, the paths), `clean.ts`
    (wikitext → text), `dump.ts` (`download`, the `<page>` reassembly, XML unescaping), `convert.ts` (OpenCC),
    `count-core.ts` / `count-worker.ts` / `count.ts` / `worker-pool.ts` (the pass), `emit.ts` (the TSV and fixture
    formats), `generate.ts` and `blog.ts`. `curl` and `bzip2` are the only system tools it shells out to.
  - `scripts/bench.ts` — the benchmark suite entry behind `pnpm run bench:font-split` (see Commands). The browser is the
    installed Google Chrome unless `KOBATO_BROWSER_CHANNEL` names another channel.
  - `scripts/bench/` — the toolchain behind it: the pure halves are unit-tested, the suite itself never runs under
    `pnpm test` or CI. The generic modules: `records.ts` (the `event<TAB>key=value` parser), `command.ts`, `stats.ts`,
    `markdown.ts` (replacement of the `<!-- bench:start … -->` blocks plus the workspace formatter),
    `tls-certificate.ts` (a self-signed localhost certificate for HTTP/2), `static-server.ts` and `browser.ts` (CDP
    throttling). The suite under `suite/`: `options.ts`, `cargo.ts` (drives the harnesses), one module per stage
    (`page-cost.ts`, `shaping.ts`, `rendering.ts`, `loading-time.ts`, `slicing-time.ts`), then `charts.ts` and
    `document*.ts` render `benchmark/*` and the marked blocks of `BENCHMARK.md` from `benchmark/results.json`. Contract:
    a stage that cannot verify its own premise fails the run (the browser must fetch exactly the predicted faces, the
    quality seams must change the bytes); every stage is `--skip`-able and then carries its numbers over from the
    previous `results.json`; the document and the charts are a pure function of that file (`--report-only` redraws them,
    and a block or chart that would carry `NaN`, `undefined` or `Infinity` fails the run — `assert-stated.ts`);
    `results.json` records the HEAD the run measured, `-dirty` when the crate or the toolchain has uncommitted changes
    and never because of the generated files, so commit the code first and the regenerated files right after the run;
    profile-guided optimization is trained and rebuilt independently three times (once under `--quick`) — cargo does not
    track a profile file, so every training run is followed by `cargo clean -p` of the crate, and the document lists the
    builds side by side because the training run decides whether PGO gains or loses; the slicing-time stage fails
    instead of recording noise when a variant of a second or more spreads more than 10% across its interleaved runs (the
    message names the `--skip` that measures only that stage again); a stage that fails keeps the stages measured before
    it in `results.json` — the document stays untouched until a run completes — and names the `--skip` that finishes the
    run; `slice-driver.ts` is a child-process entry and imports nothing beyond `node:` builtins and
    `@kobato/utils/unsafe-cast`.
- `scripts/cjk-tables/opencc/` — the four OpenCC dictionaries `opencc-fmmseg` 0.13.1 bundled (`TS`/`STCharacters.txt`,
  `TS`/`STPhrases.txt`; Apache-2.0, the `LICENSE` beside them). That lexicon differs from the stock OpenCC data
  `opencc-js` ships — it extends it with rare-character entries (暱→昵, 牠→它, 菓→果 …) and settles common one-to-many
  characters differently (里→裡, 面→麵, 着→著) — so it is data pinned on purpose: never swap these files for another
  version without re-running `corpus build`, the benchmark and the page-cost baseline. The engine is the `opencc-js`
  package (`ConverterFactory`: one dictionary group, phrases before characters, greedy longest match);
  `scripts/corpus/convert.ts` only reads the vendored files into `[key, first candidate]` pairs the way the Rust crate
  did (`#` lines skipped) and converts the stretches between ideographic description operators (U+2FF0–U+2FFF) one at a
  time — the package skips a whole such sequence unmatched where the crate converted inside it, and no dictionary key
  contains an operator or a delimiter, so the two agree everywhere else. Pinned against recorded `opencc-fmmseg` outputs
  (`tests/unit/scripts/corpus/opencc-reference.ts`).
- `tests/` — ALL Rust tests live here (`src/` carries no `#[cfg(test)]`): one file per covered module running in CI via
  `cargo test`, the end-to-end gate `chunk_integrity.rs` (slices the fixture font and checks every chunk against its CSS
  contract), the determinism gate `runner.rs` (the fixture sliced twice must be byte-identical and report no warning),
  the failure gate `failure_paths.rs` (a font built from the fixture: empty or arbitrary input and a truncated woff2
  fail fast, a font without GSUB or GPOS still slices, a font with an unreadable GSUB or GPOS still slices and reports
  exactly one warning, an unreadable cmap and `chunk_size <= 0` are rejected) and the local-only baseline/benchmark
  harnesses. Every ignored harness prints its prose report AND tab-separated `event<TAB>key=value` records (`page-cost`,
  `page-cost-size`, `shaping`, `shaping-relation`, `slicing-time`, `slicing-phase`, `slicing-face`) — the
  machine-readable contract `@kobato/font-split/scripts/bench/suite/cargo` parses; change a record and that parser
  together:
  - `tests/page_cost.rs` — the page-cost harness: three `#[ignore]`d tests serialized on one mutex (the sweep mutates
    process-global DP parameters), run with `cargo test --release -- --ignored --nocapture page_cost`. The pinned
    baseline moves in the SAME commit as an algorithm change; the per-font report (`FONT_SPLIT_BENCH_FONT` /
    `FONT_SPLIT_BENCH_PACKAGE`, `pnpm run pagecost:report`) and the λ/μ sweep (feature `bench`,
    `pnpm run pagecost:sweep`, `FONT_SPLIT_BENCH_OUT_DIR` writes every swept package to disk) are unpinned diagnostics.
  - `tests/shaping_colocation.rs` — counts the GSUB/GPOS relations (kern pairs with a non-zero adjustment, mark-to-base
    pairs of one subtable, ligatures) whose glyphs ship in the same `@font-face` of a package on disk
    (`FONT_SPLIT_BENCH_FONT` + `FONT_SPLIT_BENCH_PACKAGE`); encoded glyphs come from the Windows Unicode cmap.
  - `tests/slicing_time.rs` — one `font_split` wall time per process plus, with `FONT_SPLIT_BENCH_PHASES=1`, the
    pre-subset / subset / CSS phase split and a per-face timing (`RAYON_NUM_THREADS` sizes the pool).
  - `tests/unit/scripts/` — the TypeScript tests of `scripts/` (`tests/unit/vitest.config.ts`, the `font-split-unit`
    project, `pnpm run scripts:test`), mirroring the tooling directory. Under `corpus/`: the cleaner, the page
    reassembly and the OpenCC converter against recorded Rust reference outputs, the blog projector, the emitters, the
    counting core with fake converters, and the table generator pinned byte for byte against the committed
    `cjk_tables.rs`. Under `bench/`: the pure halves of the benchmark toolchain — record parsing, stats, block
    replacement, the TLS certificate, the static server over HTTP/1.1 and HTTP/2, the package model, the analysis, the
    charts and every generated block of `BENCHMARK.md` against the synthetic `results-fixture.ts` (in-package helpers
    resolve through the `./tests/*` export), the lossless read of `results.json`, the commit stamp of a run in a scratch
    repository and the suite orchestration (checkpoint on failure, finishing with `--skip`) against fake stages. No
    module mock is registered — `run.ts` takes its collaborators as one `SuiteDependencies` object and `formatFile` its
    command runner — so the tree shares the project worker.
- `tests/fixtures/` — `fonts/NotoSansCJKsc-Regular-zh-l1.woff2` (OFL-licensed Noto Sans CJK SC subset; provenance and
  regeneration in its `LICENSE.md`) and `pages/*` page corpora as sorted codepoint sets — the held-out zhwiki pages
  (excluded from the frequency counts) and a production-blog snapshot (independent of the training corpus); provenance
  in the file headers.

## Toolchain pins

- Rust edition **2024** (`Cargo.toml` + `rustfmt.toml`); stable toolchain via `rust-toolchain.toml`.
- `.cargo/config.toml` sets `HARFBUZZ_SYS_NO_PKG_CONFIG=1` — without it `harfbuzz_rs_now` links the SYSTEM harfbuzz via
  pkg-config (segfaults in tests and leaves a Homebrew dylib dependency in the addon, breaking SEA distribution); the
  flag forces the vendored, statically linked harfbuzz so `font-split.node` stays self-contained.
- Build prerequisites are a stable Rust toolchain and a C++ compiler only (harfbuzz_rs_now and woff compile their
  vendored C/C++ via `cc`); cmake is NOT required since the opencc-rs build script was removed.

## Trimmed vs upstream

Removed: protobuf (`crates/proto`, prost/tonic-build), all other bindings (`packages/ffi*`, `ffi-py`, `grpc`, `wasmer`,
`wasm-edge`, `vite`), the CLI bin + clap, preview-image SVG (`gen_svg`), test-HTML emission, `reporter.bin` /
`OutputReport`, user-defined `subsets`, `polyfill`, the `with_extra` feature split (always on), config fields nothing
reads (`out_dir`, `target_type`, `build_mode`, `multi_threads`, `chunk_size_tolerance`, `max_allow_subsets_count`), the
OpenCC-based build-time traditional-char derivation (replaced by official regional character lists), and the
`regex`/`lazy_static` crates (hand-rolled name-template parser + `std::sync::LazyLock`). Disk-fixture tests referencing
the upstream demo fonts were dropped. Output = `result.css` + `*.woff2` only.

## Commands

- `pnpm --filter @kobato/font-split run build` — `napi build --release --output-dir .` (`@napi-rs/cli`): builds the
  cdylib, places it at `font-split.node`, and regenerates `src/binding.d.ts`. Required once per machine before
  `pnpm dev` / server tests touch font slicing, and in CI before `sea:build`. Requires a stable Rust toolchain
  (`rust-toolchain.toml`) and a C++ compiler.
- `pnpm --filter @kobato/font-split run test` — `cargo test`.
- `pnpm --filter @kobato/font-split run lint` — `cargo fmt --check`, then `cargo clippy --all-targets -- -D warnings`;
  CI runs it after the tests.
- `pnpm --filter @kobato/font-split run pagecost:report` — the page-cost report of every page corpus for one real font
  (local only: needs `data/fonts/calendar.ttf` or `FONT_SPLIT_BENCH_FONT`).
- `pnpm --filter @kobato/font-split run pagecost:sweep` — the DP λ/μ sweep on that font (`--features bench`; local
  only); the retuning evidence comes from this run.
- `pnpm run bench:font-split` (repository root) — the whole suite on the production fonts: every harness above, the
  throttled-browser loading time, the rendering check and the slicing-time variants, then `BENCHMARK.md`, the charts and
  `benchmark/results.json` are regenerated. Local only: needs `data/fonts/`, Chrome, Rust and about half an hour
  (`--quick` smoke-runs the pipeline, `--skip <stage>` carries a stage over, `--report-only` redraws from results.json).
- `pnpm --filter @kobato/font-split run scripts:test` — the `scripts/` unit tests (the `font-split-unit` Vitest
  project).
- `pnpm --filter @kobato/font-split run cjk-tables:generate` — regenerate `src/unicode/cjk_tables.rs` from
  `scripts/cjk-tables/` after changing the vendored lists or the frequency TSVs; `corpus:generate` is the same
  generator. The output must stay byte-identical unless the data changed — it feeds the algorithm fingerprint.
- `pnpm --filter @kobato/font-split run cjk-tables:update` / `corpus:update` — the full table-update flow: generate,
  `cargo test`, then rebuild `font-split.node`.
- `pnpm --filter @kobato/font-split run corpus:download` / `corpus:build [-- --workers <n>]` — fetch the pinned zhwiki
  dump and run the one-pass frequency/fixture build (local only, never CI; `build` needs `curl`, `bzip2` and the 3.4 GB
  dump and takes about seven minutes on 16 workers).
- `pnpm --filter @kobato/font-split run fixture:blog <kobato.db> <out>` — regenerate the production-blog page fixture
  through `scripts/corpus.ts` from a Kobato content database (local only; it is opened read-only through `node:sqlite`,
  so hand it a copy together with its `-wal`; a new snapshot needs re-pinning the `blog` baseline).

## Syncing from upstream

Re-vendor the upstream `release` branch's core `src/` and the helper crates (`cn-font-utils`, `unicode-range`) into the
flat layout above, then re-apply the transformations: no `cn_font_proto`/`prost` imports, config/output types from
`src/config.rs`/`src/output.rs`, no reporter/gen_svg/test_html/subsets call sites, helper imports rewritten to
`crate::{utils,unicode}`. The CJK tables are NOT synced anymore: they are Kobato-owned (`unicode/cjk_tables.rs` +
`unicode/cjk.rs` + `scripts/corpus/`). The script areas in `unicode/mod.rs` mirror upstream except six corrections: Lisu
and Vai point at their real Unicode blocks, and HANI, LAHU, ZHUANG and NAXI_DONGBA are gone (their ranges named
unrelated blocks, and three of the scripts have no Unicode block at all), so `create_default_unicode_area()` has 32
areas. `src/pre_subset/` is Kobato-owned as a whole — re-vendoring it would drop the DP chunker, the per-pack probes and
the shaping closure; take upstream fixes from that directory by hand. `cargo test` plus the server-side real-TTF
`slice.test.ts` are the drift guards.

Upstream was last reviewed at `c630a14` (2026-11-27, 136 commits past the base): beyond the two ported fixes and the
declined `5cdc0ae` nothing applies — the rest is refactoring with byte-identical output, packaging, or superseded here
(`d6e5d2b`'s estimator by the per-pack probes, `2bb1176`'s error model by the binding's `catch_unwind`, `b061b06`'s
positional language tags that this fork corrected, `3f48c93`'s blake3 names that would lengthen every `url()` of
`result.css`, and the woff 0.4.0 pin that only works around a GCC 13+ build failure 0.6.4 does not have). The table-read
diagnostics follow upstream `5882e6d`.
